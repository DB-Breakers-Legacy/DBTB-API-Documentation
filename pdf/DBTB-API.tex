\section{End-to-End Request Sequence}
%==============================================================================

Combining the observed calls gives the following approximate application
sequence:

\begin{lstlisting}
1. /000000/api/user/auth
       |
       | authentication
       v
   session established
       |
       v
2. /000000/api/user/get_country
       |
       | country lookup
       v
   "GB"
       |
       v
3. /000000/api/user/get_tracking_num
       |
       | tracking number retrieval
       v
   "LXDA-45J98PDC7NL"
       |
       v
4. /025348/api/close/get_close_info
       |
       | language = "en"
       v
   close/status configuration
       |
       v
5. /025348/api/user/create_user_info
       |
       | country = "GB"
       | language = "en"
       | Steam ID
       v
   user information processing
       |
       v
6. /025348/api/adjustment_data_manage/read
       |
       | no endpoint arguments
       v
   56,327-byte adjustment-data blob
\end{lstlisting}

The exact ordering shown here follows the sequence of captures supplied for
analysis; it should not be interpreted as a complete application startup
state machine.

\section{Conclusions}
%==============================================================================

The packet captures establish a coherent HTTP/2 MessagePack application
protocol.

The most significant properties are:

\begin{enumerate}
    \item All observed API operations use HTTP/2 \texttt{POST}.
    \item The APIs are transported over HTTPS\@.
    \item MessagePack is used for the application data.
    \item Requests use a recurring client context containing title, user,
          session, and platform information.
    \item Game-specific requests additionally contain a version field.
    \item Endpoint-specific arguments are represented as a second array.
    \item Successful responses use HTTP status \texttt{200}.
    \item Responses contain a common result/date/session metadata object.
    \item The session value evolves across successive requests.
    \item The country API returns \texttt{GB}.
    \item The tracking-number API returns
          \texttt{LXDA-45J98PDC7NL}.
    \item The user-information API supplies country, language, and Steam ID\@.
    \item The close-information API accepts a language argument of
          \verb|"en"|.
    \item The adjustment-data API returns an opaque 56,327-byte encoded
          string inside a 56,411-byte MessagePack response.
\end{enumerate}

The resulting high-level protocol can therefore be summarized as:

\begin{lstlisting}
Client
  |
  | POST /endpoint
  | common MessagePack context
  | endpoint arguments
  v
Server
  |
  | 200 OK
  | result metadata
  | updated session
  | endpoint-specific data
  v
Client
\end{lstlisting}
